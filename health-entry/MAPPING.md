# 数据映射模型说明

这份文档说明：健康资料入口**采用了哪些数据**，以及这些数据**如何换算成游戏的初始人物状态**（属性、五行、护持任务）。

面向对象：游戏开发 / 产品 / 希望了解「为什么长辈的血压会变成这个灵力值」的任何人。

---

## 1. 采用的输入数据（三类）

入口把「图片 + 文字」汇总成一份结构化 document，只取下面三类常规数据：

| 来源 | 字段 | 说明 |
| --- | --- | --- |
| 体检报告图片 | `groups[].items[]` | 常规体检指标（血常规、血糖血脂、肝肾功能、血压心率、BMI 等） |
| 病历 / 文字病史 | `history[]` | 疾病史：`condition`（病名）、`onset`（起病时间）、`status`（ongoing/past/unknown） |
| 用药单 / 文字用药 | `medications[]` | `name`（药名）、`dose`（用法）、`purpose`（用途，如 降压/降糖）、`status` |

**筛选原则**：只保留能落到五行关键词白名单里的「常规」指标；罕见、非常规的专科检查（基因检测、罕见肿瘤标志物、特殊免疫指标等）**自动舍去**，不进规则引擎。

---

## 2. 五行对应表（核心映射）

每个五行元素对应一个「方向 + 游戏属性」，并由一组关键词把指标、病史、用药归到它下面。

| 五行 | 名称 | 对应游戏属性 | 覆盖的常见数据（关键词举例） |
| --- | --- | --- | --- |
| 金 `metal` | 金 · 护息 | 防御 `defense` | 血氧、呼吸、肺、胸片、哮喘、慢阻肺、止咳平喘药 |
| 木 `wood` | 木 · 舒展 | 身法 `speed` | 血糖、血脂、转氨酶、肝、糖尿病、脂肪肝、降糖降脂药 |
| 水 `water` | 水 · 藏养 | 体力 `stamina` | 肾、肌酐、尿酸、尿检、骨密度、痛风、护肾利尿药 |
| 火 `fire` | 火 · 心脉 | 灵力 `spirit` | 血压、心率、心电、心脏、高血压、冠心病、降压护心药 |
| 土 `earth` | 土 · 纳养 | 气血 `hp_max` | BMI、体重、营养、胃、血常规、贫血、护胃补铁药 |

> 关键词的完整清单在 `rules.py` 的 `ELEMENTS` 里，需要调整对应关系时只改那里即可。

### 每个元素的状态判定

按优先级：

1. 有**异常指标**，或有 **ongoing/unknown 状态的病史** → `needs_care`（需护持，生成护持任务）
2. 有正常指标、**past 病史**（已痊愈/已手术）或**在服用药** → `stable`（稳定）
3. 什么都没有 → `unknown`（未提供相关资料，中性值 50）

这样「病史 + 用药」也能让五行落到 stable/needs_care，而不是大量显示「未提供相关资料」。

## 3. 属性值怎么算出来

10 个游戏属性由 `rules.py` 确定性计算，主要分两步：

**第一步：证据特征（0–100）**。由资料量计算：
- `data_completeness`（资料完整度）：有效指标数 + 病史数 + 用药数越多越高。
- `function_capacity`（活动能力）：默认中性 50；报告/病史出现「活动受限、卧床、偏瘫」等才下调到 40。
- 其余（`plan_coverage`、`family_support` 等）首次注册没有数据，用中性值 50。

**第二步：换算公式 + 五行修正**。例如：

```
hp_max    = clamp(80 + 0.25×function_capacity + 0.15×data_completeness, 80, 130)
spirit    = clamp(20 + 0.30×data_completeness + 0.20×routine_stability + 0.15×plan_coverage, 20, 85)
stamina   = clamp(20 + 0.45×function_capacity + 0.10×self_reported_energy, 20, 90)
```

然后**五行状态轻微修正对应属性**（体现「体检 → 五行 → 属性」的对应关系）：

| 五行状态 | 对对应属性的修正 |
| --- | --- |
| `stable` | +6 |
| `needs_care` | −4 |
| `unknown` | 0 |

修正幅度很小，**异常不会把属性扣成残血**——这是刻意的：健康异常只进入「护持任务」这条关怀线，不变成惩罚。

---

## 4. 护持任务（tasks）

每个 `needs_care` 的元素生成一条任务：

```json
{ "task_id": "care_fire_001", "title": "火·心脉 护持",
  "detail": "核对 2 项相关指标/病史，整理复诊问题", "status": "pending" }
```

游戏侧拿这些任务做「关怀/护持」玩法，而不是扣血惩罚。

---

## 5. 完整流程一图

```
体检报告图 + 病历图 + 用药图（多张）
        ↓ 视觉模型识别（recognizer.py）
结构化 document：groups + history + medications
        ↓ 规则引擎（rules.py）
五行状态（stable / needs_care / unknown）
        ↓
10 个属性 + 五行共鸣值 + 护持任务 + 准备度
        ↓
baseline JSON（游戏读取）
```

---

## 6. 快速对照示例

输入：`血压 152/95（abnormal）`、病史 `高血压 ongoing`、用药 `氨氯地平（降压）`

- 火 `fire`：命中「血压/高血压/降压」→ 有异常指标 + 持续病史 → `needs_care`，生成「火·心脉 护持」任务
- 灵力 `spirit`：在基础值上 **−4**
- 其它五行若没有相关数据 → `unknown` / 中性 50

这就是「血压 → 火 → 灵力 → 护持任务」的完整对应链。
