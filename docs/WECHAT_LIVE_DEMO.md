# 现场微信扫码与灵宠联动

目标：体验者在游戏登录自己的账号，选择对应角色，从灵宠打开微信二维码；扫码者确认角色和任务共享后，在真实微信与bot交流，游戏自动显示同一任务的进展。当前实现针对现场同一台演示电脑，多个账号分别连接；不是已部署的公网注册服务。

## 启动

需要 Python（Flask、requests）、Node.js 24、Godot 4.7.2。双击 `tools/启动微信实机联动.cmd`。引擎可放在 `work/runtime/`，也可用 `GODOT_BIN` 指定路径。

首次在其他电脑安装服务依赖：

```powershell
python -m pip install -r tools/wechat_live/requirements.txt
npm ci --prefix tools/wechat_live
```

```powershell
python -B tools/wechat_live/run.py --godot "你的Godot引擎完整路径"
```

只启动账号、微信和任务服务：

```powershell
python -B tools/wechat_live/run.py
```

游戏需带环境变量 `XIUXIAN_ACCOUNT_URL=http://127.0.0.1:8010`、`XIUXIAN_WECHAT_LINK_ENABLED=1`；一键启动器自动设置。不使用 `--preview` 或 `--wechat-link-demo`，不创建假家人或共用一个固定账号。

## 现场操作

1. 在游戏注册/登录体验账号。可以选择本人角色；需要连接家人时，先创建对应家人并完成游戏内共享确认。
2. 选择一只灵宠，打开灵宠面板，点击“连接微信 / 查看连接”。核对当前角色后，点击“打开微信扫码窗口”。
3. 用体验者自己的手机微信扫码并确认。在浏览器核对游戏角色，勾选任务共享，然后点击“确认角色并连接”。
4. 在微信机器人会话中依次发送：

```text
今日任务
我每天晚饭后散步
我今天已经散步了
今日任务
```

演示可使用虚构生活安排。第二句话建立明确的每日散步记录任务，第三句话记录本人完成反馈；灵宠约2秒刷新，任务页显示微信来源和完成状态。聊天窗口不必保持打开。

也复用了既有老人端模块的“已有用药安排 → 补齐信息 → 本人确认完成”流程；每日多次用药尚需精确执行实例，目前拒绝把一次反馈当成全天完成。现场优先使用上面的散步流程。

5. 体验下一位时，在游戏退出当前账号，登录下一位账号，再选择角色扫码。账号、微信发送者、任务和消息回执各自隔离。同一微信不能同时绑定到两个账号。
6. 解除连接使用“断开当前角色的微信”；停止新的共享与待发送回复。重新连接必须再次扫码确认。

## 保存与恢复

`work/wechat-live/`保存独立账号、连接、任务、微信凭证和传输队列，`work/wechat-live/player-cache/`保存本次环境下的游戏存档；`work/`被Git忽略。不要上传该目录，或将其当成普通截图分享。F盘已有存档和刚才的扫码凭证没有自动迁移到这里。

重启服务后，已激活微信连接恢复轮询；待处理入站消息与待发送回复继续处理，任务事件重复送达不会重复应用。游戏登录会话过期时重新登录即可。微信登录被平台判定失效时，界面显示收发未连接，需要断开旧连接、重新扫码。

## 实现与验证边界

- `live_host.py`复用现有Python账号验证和老人消息处理代码，新增账号范围的业务绑定与持久任务投影。扫码与共享确认是两个步骤。
- `gateway.mjs`实现腾讯官方iLink的二维码、长轮询和文字回复；保留精确消息编号与原会话context token。游标与入站队列一同持久化，重投只返回原回执。只处理扫码者本人私聊。
- Godot从已经验证的账号服务读取任务。微信bot token、内部服务token和聊天原文不进入游戏。
- 当前联动任务是只读展示，不接入C的正式奖励账本，不改变抽卡/装备或100灵气规则。语音仅在腾讯已提供文字转写时处理；图片、文件不做完成判定。自由聊天默认使用已有确定性处理，不调用外部模型；可在明确配置模型后加`--allow-models`。
- 当前宿主为本机联合演示用途；公网、多电脑访问需另做HTTPS、部署与客户端入口，不要直接开放本机端口给互联网。

通道字段与登录步骤依据[腾讯官方协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol.md)、[官方登录源码](https://github.com/Tencent/openclaw-weixin/blob/main/src/auth/login-qr.ts)，应用字段对应官方插件2.4.10。

自动检查：

```powershell
python -B tests/test_wechat_live.py
node --test tests/wechat_gateway_test.mjs
```

服务测试使用隔离账号和模拟腾讯回执，覆盖共享确认、账号隔离、解绑、去重、重启后任务保存、既有老人消息模块、登录与消息传输协议。原生界面与真实微信结果见下；部署到新环境后应重新执行现场流程。

如需要保持既有完整本地游戏的改动，可创建独立副本后验证：

```powershell
python -B tools/wechat_live/prepare_playtest.py --source "已有完整像素版的目录"
python -B tools/wechat_live/test_native.py --screens
```

`prepare_playtest.py`用于尚未添加本轮连接入口的本地版本，拒绝覆盖已有目标目录。`--project`可以指定独立游戏目录。`run.py --experience --godot "引擎路径" --project "游戏目录"`会使用独立生成的联测账号，自动打开连接入口；账号凭证仍只写入被忽略的本机数据目录。
