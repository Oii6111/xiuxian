# 家族修真录 · 松风四式（Godot 像素闯关）

> **B/C/D 已整合**：年轻人在网页玩游戏（C 服务同时托管客户端），老人只用微信扫码绑定 AI Bot。运行与接口见 [docs/BCD_INTEGRATION.md](docs/BCD_INTEGRATION.md)。

当前开发目录：`F:\godot\xiuxian2`。保留现有像素仙村、男女角色、妖龙精灵和战斗背景；当前包含健康属性、二十 Boss 问道长廊和四个技能，没有引入旧项目的 3D 建模或场景。

## 运行

用 Godot 4.7.2 打开本目录 `project.godot` 后按 F5；也可双击 `启动试玩.cmd`。启动先登录或注册子女账号，再进入“我的角色 + 两位家人”页面。本人角色独立保留，不占两个家人名额。注册首次请求时会自动启动本机账号服务，需要 Python 3。

新增统一内核 `GameKernel`，提供时间、事件、随机、配置、状态存档、迁移、命令路由与审计，以及七个独立系统入口。C 已接入赛季查询与网络依赖；其余客户端业务接口明确返回 `NOT_IMPLEMENTED`，供 A/B/D 逐项接入。

## 三分钟体验

1. 注册并登录自己的账号后，在“我的家人”添加家人，填写姓名、年龄、性别、关系与可选修仙称号；确认本人同意或家人同意后，代填报告或文字资料，分析并确认基础状态。
2. 从“属性试炼 / 属性闯关”进入问道长廊。二十只 Boss 共用一条可横向行走的长廊，每扇门展示对应的 Boss、战场预览和首通标记。
3. A / D 行走、Shift 加速、滚轮浏览；点击 Boss 直接进入它的独立战场，或走近按 E。上方区域按钮和下方 01—20 编号可快速定位。
4. 使用 J 普攻、1 听风剑诀、2 / 空格踏云步、3 / K 云罡护体。普攻需靠近命中才回灵，体力自动恢复。
5. 首通两个不同 Boss，解锁 4 / R 饕餮归元。吐纳时移动变慢，受到实际伤害会中断。
6. 战斗结束后返回长廊会保留位置。回健康档案补充资料并确认新档案，下一场战斗采用更新后的属性；既有通关进度保留。未绑定报告的角色仍可使用明确标注的模拟改善。
7. 演武台可练习同一套四技能，不增加首通或贡献。每次入场生命、灵力、体力补满；战斗不扣健康属性。

C 的本地后端已实现：账号密码登录、任务实例、绑定授权、事务账本、抽卡、D 接缝、通知重试及个人 WebSocket 同步。进入 `server/` 后执行 `npm ci`、`npm run dev` 启动；`npm run demo` 运行隔离模拟闭环。详见 [后端说明](server/README.md) 和 [团队合并指南](docs/BACKEND_INTEGRATION.md)。本轮没有部署远程服务器，真实微信与 AI、A/B/D 业务仍待合并。

## 长廊与战场

总共二十只 Boss，不再展示五条属性各十档的挑战列表。所有门都可点击，建议培养档位用于提供难度参考，不作为属性入场门槛。

- 长廊：使用新制作的像素古寺走廊底图，角色可以实际行走，镜头横向跟随；鼠标滚轮可以独立浏览。
- 战场：`scenes/trials/b00.tscn` 至 `b19.tscn` 为二十个独立场景入口，各自绑定名字、精灵、出生点、场景布置和专属氛围。
- 底图：基于 PR #2 下载的七张地域美术。同地域 Boss 会共用地域底图，但拥有各自的场景配置；当前并非二十张独立绘制的背景。
- 结算：保存每只 Boss 的首通与最佳用时；返回长廊保留角色和镜头位置。首通两个不同 Boss 解锁饕餮归元。
- 战斗：沿用当前普攻、四技能与红圈预警原型，专属 Boss 招式和进一步平衡后续另做。尚未加入联网排行。
- 技能难度：10—100 档的前摇从 0.85 秒逐步缩短至 0.45 秒，椭圆攻击范围（完整宽×高）从 250×160 扩大到 460×300。预警与命中判定共用范围参数；演武练习保留原来的宽松节奏。

## 操作与四技能

| 操作 | 效果 |
|---|---|
| WASD / 方向键 | 移动；仙村 Shift 奔跑、E 交互 |
| J | 基础普攻，近身命中恢复 5 灵力 |
| 1 / Q 听风剑诀 | 18 灵力；路径剑气，可命中多个目标 |
| 2 / 空格 踏云步 | 24 体力；沿输入方向位移与短暂闪避 |
| 3 / K 云罡护体 | 24 灵力；防御属性决定有限护盾吸收量 |
| 4 / R 饕餮归元 | 首通两关解锁；45 灵力，吐纳后恢复生命 |
| Esc | 战场返回长廊；长廊返回仙村；关闭普通面板 |
| F12 | 截图至 `output/pixel-screenshot.png` |

普攻不计入四技能。聚宝阁开放武器、衣服、鞋子、饰品四个装备槽；装备独立增加游戏战斗属性。饕餮玉扣仍是固定角色特征，以 2D 像素特效参与护盾与归元表现。技能数值与各档血量、伤害为玩法验证初值。

## 登录注册、本人角色与两位家人

- 用户名为 3—24 位字母、数字或下划线，密码为 8—128 位；注册时设置自己的昵称和修仙形象。支持密码登录、退出和换账号。
- 用户名和密码由独立 HTTP 账号服务验证。密码使用随机盐 PBKDF2-HMAC-SHA256 存储，会话令牌只放在内存；数据库与个人存档不提交 Git。
- 账号区域显示“我的角色 · 本人”；下面始终有两个老人位置。本人不能添加到家人位置中。本人和每位老人的任务、灵气、装备、属性和通关分别保存。
- 不同账号使用不同的本机存档文件：编辑器 `output/accounts/{account_id}.json`，运行版本 `user://accounts/{account_id}.json`。当前不提供跨设备存档同步。
- 首次登录发现旧档时，可以选择保留旧进度或使用新角色。原单角色进度归入本人；旧 schema 7 中未填写关系的 `elder_legacy` 或明确标为本人者归回本人，已明确填写老人关系的档案保留。导入前备份为 `*-before-accounts-v8.json`，同一旧档只能归属一个注册账号。
- 家人卡片可添加老人、编辑资料或代填健康信息；未提交的健康输入仅保留在当前表单中，关闭后清空。战斗和识别进行时先完成或取消再切换。
- 当前账号服务运行于本机 `127.0.0.1:8010`，尚未部署公网。手动启动与接口说明见 `server/account/README.md`。

## 灵宠相伴

四位免费同行伙伴：云团小狐、葫芦小龙、莲叶团雀和药草小鹿。首次登录可选择灵宠、设置昵称，之后可自由更换；灵宠跟随地图角色，并可通过点击或左侧入口打开聊天。

灵宠偏好属于账号，不占本人或两位老人位置。聊天按当前角色读取游戏任务和进度，提供文字与导航，不能发奖、改属性或执行脚本；退出账号清空对话。默认使用本地向导，可选 HTTP 服务遵循 [聊天接口说明](docs/COMPANION_API.md)，账号令牌只向显式授权的源地址发送。

本轮同时加强账号会话隔离、健康确认归属、保存失败回滚、旧档隐私和抽卡回执校验。现有 70/700 抽卡价格、五档品质、四个槽位、每日 100 灵气、四技能和二十 Boss 规则保持。详见 [逻辑与账本审查](docs/c-ledger-alignment-review.md) 和 [版本化本地规则清单](data/pixel-game-rules.v1.json)。

## 聚宝阁：每日习惯、祈愿与装备

- 主地图左侧商铺前新增聚宝阁宝箱，可点击地点自动前往，或走近按 E；底部导航也有聚宝阁。
- 每天首项由家属确认的有效习惯记录获得 100 灵气，同时保留修为 +10、灵印 +1。当天第二项或重复记录不重复发奖，漏记不清零。
- 新钱包从 0 开始，与旧版回合试玩的 `qi` 和战斗技能使用的灵力分开。单抽 70，十连 700，积攒七天可十连。
- 白／蓝／紫／金／红分别为普通、精良、史诗、传说、神话；卡片与装备槽按品质描边，并显示品质名称。
- 概率按首次确认的五项基础属性平均值固定，在初始属性 100 的 `[55,30,11,3.5,0.5]%` 与初始属性 0 的 `[35,33,22,8,2]%` 之间线性变化。旧档案 HP 大于 100 时只在此抽卡规则内截为 100。档案更新、换装备不改变已固定概率。
- 十连至少一件史诗或以上；自然结果不足时仅把最后一件提升至史诗。页面展示的是保底前概率。
- 五种装备模板包括攻击武器、防御衣服、生命衣服、体力鞋子、灵力饰品，每个槽位只穿一件；重复装备分别保留。精良踏风靴提供体力上限 +10。
- 点击结果卡可查看详情、比较当前装备并穿戴；背包支持槽位筛选。加成只影响下一场战斗快照，不改变健康属性。
- 扣费、装备和请求回执在同一份本地存档中原子保存后才显示动画；失败回滚。跳过动画、关闭页面、重启后均可找回最近结果，同一请求重试不重复扣费。
- 旧版存档进入当前家人系统前统一备份为 `*-before-accounts-v8.json`。保留既有健康档案与通关；从装备系统之前的版本升级，若当天已确认有效记录，补入当天 100 灵气，不补历史奖励。
- 当前为本地单机实现，健康记录仍沿用现有家属确认入口；尚未接入微信核验或服务端权威账本。

## 健康接口与存档

已按 GitHub `1f356a0` 的最新版 `health-entry` 接入原生像素界面：启动选择家人 → 为选中的家人填写信息，可选择形象 → 上传多张体检报告 / 病历 / 用药图片及文字信息 → 使用 `qwen3-vl-plus` 提取 → 原版规则引擎计算 → 预览最终属性 → 确认锁定后进入仙村。新版已移除五行，改为身体系统对应属性。药品通用名与商品名分离，每条资料只归入一个系统；创建页只保留玩家自行上传和填写资料，不显示样例按钮或相关提示。

在 `health-entry/.env` 填写 `LLM_API_KEY`，保留 `LLM_MODEL=qwen3-vl-plus`。游戏尝试自动启动本地服务；连接失败时双击 `health-entry/start.bat` 再重新连接。填写配置后无需重启。队友先运行 `python -m pip install -r health-entry/requirements.txt`。

可添加最多 6 张 PNG / JPEG / WebP（单张 10 MB，合计 30 MB），也可填写文字病史、用药与基本信息。文字模式只用规则、不调用模型。模型识别和文字计算分别标明。姓名、年龄、性别和关系均为必填，姓名与年龄初始留空，性别和关系也不预填。未上传照片时只显示文字占位，上传后才预览所选报告。游戏界面仅展示最终属性，不提供计算依据或公式入口。确认的姓名用于家人识别，修仙称号显示在角色旁；确认前不改数值，修改资料后需重新分析。

接口的 `hp_max`、攻击、灵力、体力直接进入战斗，不重复套用旧评分换算。保存洞察、心志、身法、气运和属性依据，不增加新的战斗机制。补充报告不会清空通关和技能解锁。完整说明见 `docs/health-entry-integration.md`；未绑定报告的角色仍兼容旧版 JSON 和模拟档案。

计划记录继续每日去重并积累修为，不把一次记录自动解释为真实健康改善。战斗生命归零仅表示本局失败，不根据健康分数自动推断现实死亡。战败保留用时、伤害、受击等事实反馈，详细复盘和线上竞技后续再做。

存档 schema 8 分别保存注册账号、本人角色、两位老人及当前角色；旧存档导入前统一备份为 `*-before-accounts-v8.json`，旧版已解锁的归元技能继续保留。编辑器使用 `output/local-save.json`，运行版本使用 `user://songfeng_pixel_progress.json`。自动测试、预览截图不写玩家存档。

## 团队协作

仓库：<https://github.com/Oii6111/xiuxian>。

仓库所有者在 GitHub 的 **Settings → Collaborators** 中邀请队友，队友接受邀请后即可推送代码。每个人先克隆到自己的电脑，用 Godot 4.7.2 打开 `project.godot`；首次导入时会自动生成 `.godot/` 缓存。启动脚本中的引擎路径为本机路径，其他电脑可直接从 Godot 编辑器启动。

```bash
git clone https://github.com/Oii6111/xiuxian.git
cd xiuxian
git switch -c feature/your-task
```

开始新任务前，先回到 `main` 并拉取最新代码，再创建自己的功能分支：

```bash
git switch main
git pull --ff-only
git switch -c feature/your-next-task
```

完成修改并在 Godot 中验证后，提交并推送自己的分支，然后在 GitHub 发起 Pull Request，合并到 `main`：

```bash
git add .
git commit -m "Describe your change"
git push -u origin HEAD
```

Git 支持多人分别修改、提交和合并；需要实时一起编辑时，要另用实时协作工具。分工时尽量由一人负责一个 `.tscn` 场景或 `.tres` 资源，减少同时修改同一文件产生的冲突。脚本 `.gd`、对应 `.uid`、场景、素材和 `.import` 导入配置应一并提交；`.godot/`、本地存档、日志和更新备份已由 `.gitignore` 排除。
