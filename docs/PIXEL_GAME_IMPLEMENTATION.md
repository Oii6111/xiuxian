# 家族修真录 · 松风四式 / 像素闯关设计

## 当前方向

保留当前 Godot 2D 像素仙村、人物精灵、妖龙和像素战斗背景。不得从旧 3D 项目导入建模、场景、材质或环境素材。旧项目仅作为状态与数据配置分离的代码逻辑参考。

角色根据外部健康评估档案获得五项 0—100 属性：生命、攻击、防御、灵力、体力。体检单、病历到属性评分的量化由后续服务接口负责；当前只接收已评估的属性 JSON，提供明确标注的模拟档案。

产品评分端点以 100 表示健康目标端、0 表示严重受损端。分数不是本地医学诊断，本地不得根据 0 分推断死亡或改变家人的现实生命状态。战斗生命归零仅表示这一局游戏失败。

## 五属性与临战资源

| 属性 | 用途 |
|---|---|
| 生命 | 决定战斗最大生命 |
| 攻击 | 决定普攻和听风剑诀伤害 |
| 防御 | 降低来袭伤害，提高云罡护盾吸收量 |
| 灵力 | 决定最大灵力；剑诀、护盾、恢复共用 |
| 体力 | 决定最大体力；踏云步消耗，自动恢复 |

属性保存于角色档案；当前生命、灵力、体力属于单局战斗，入场补满。战斗不会扣除健康属性。更新健康档案在下一场生效，已经通关的进度保留。完成个人计划继续积累修为与原有家庭记录，不假定一次记录自动改善真实健康评分。

## 四技能与独立装备养成

普攻为基础动作，不计入四技能。普攻需要在目标范围内命中，回灵 5 点。

| 技能 | 操作 | 暂定消耗 | 规则 |
|---|---|---|---|
| 听风剑诀 | 1 / Q | 18 灵力 | 青绿淡墨剑气穿过路径上的目标，攻击属性决定伤害 |
| 踏云步 | 2 / 空格 | 24 体力 | 朝移动方向位移；没有输入时沿上次朝向；有短暂闪避窗口 |
| 云罡护体 | 3 / K | 24 灵力 | 3.2 秒有限吸收护盾，7 秒冷却，防御提高吸收量 |
| 饕餮归元 | 4 / R | 45 灵力 | 吐纳 1.1 秒、移动减速、实际受伤会打断；15 秒冷却 |

先开放前三式。首通两个不同关卡后解锁饕餮归元；重复刷同一关不推进解锁。玉扣继续作为角色固定视觉特征；新增装备系统使用独立的武器、衣服、鞋子和饰品槽，不改变四技能。临时技能数值只用于验证资源循环，不是最终平衡数值。

## 闯关结构：问道长廊与二十战场

仙村属性试炼入口直接进入一条横向延伸的像素古寺长廊。二十个传送门依次陈列听雷、朽梁、涩节、窃荣、乱律、窄焰、赤棘、积璧、薄丹、失稷、闭岚、灼羽、缄风、沉砂、滞潮、壅川、漏夜、失简、晦鳞和执衡。

角色可以行走，镜头跟随；滚轮浏览、区域按钮和二十个编号可快速定位。点击 Boss 直接进入对应战场，走近按 E 也可进入。所有门可选；建议培养档位不构成属性门槛。战斗结束或按返回键回到长廊，角色位置与镜头保留。

每只 Boss 有独立 `.tscn` 场景入口，绑定自身像素精灵、场景名称、地域底图、出生点、尺寸、阵纹和环境粒子。当前七张地域底图供二十个场景配置使用，同地域会共用底图；二十张独立绘制的战场背景不在这次实现范围内。原下载的场景入口已适配为本地长廊，不导入 PR 的其他代码。

首通与最佳用时按 Boss ID 唯一保存，重复挑战不重复计算首通。首通两个不同 Boss 解锁归元。每完成四只 Boss 推进一阶段境界，二十只全部完成后为化神圆满；旧版已经积累的境界与技能资格保留。旧五属性各十档的字段只供存档兼容，当前不再提供五十关界面。

四技能和现有攻击预警规则保持可玩，二十 Boss 的专属招式与深度平衡后续再设计。

当前只保留事实结算：本局用时、造成伤害、受到伤害、受击次数。复盘建议、排行榜、多人竞技和竞技规则后续再讨论。当前是本地闯关，不把本地记录描述为在线排行。

## 聚宝阁与灵气装备循环

主地图左侧商铺增加聚宝阁地点、宝箱表现、步行导航和 E 交互。每日有效习惯记录首次确认时增加 100 灵气，与修为 +10、灵印 +1 一起持久化；同日多项不重复奖励，漏记不清零。新钱包与历史回合资源、单局灵力分开，单抽 70、十连 700。

装备品质为普通（白）、精良（蓝）、史诗（紫）、传说（金）、神话（红），品质由描边框、名称和出货光色共同表达。武器增加攻击，衣服增加防御或生命，鞋子增加体力，饰品增加灵力；每槽一件，重复装备各自保留。背包提供筛选、详情、当前装备比较、穿戴和卸下。

抽卡依据为首次确认的基础档案五属性归一化平均值，永久固定并记录原档案 ID。属性 100 时基础概率依次为 55%、30%、11%、3.5%、0.5%；属性 0 时为 35%、33%、22%、8%、2%，中间线性插值。后续改善不降低扶持，装备不影响概率。未确认基础档案时不能抽取。

每次十连至少一件史诗或以上，自然结果不满足时仅提升最后一件，不降低已抽出的高品质。先原子保存扣费、装备和回执，再播放可跳过动画；相同请求 ID 幂等，保存失败回滚。重开或重启可恢复最近结果。装备只叠加游戏战斗属性，沿用入场快照，不能反写健康档案。

旧存档升级前备份并保留所有既有进度，首次使用时固定现有基础档案；升级当天已有确认记录时补入当天 100 灵气，历史不追溯。当前仍为单机家属确认流程，未来可由服务端替换结算边界。

## 一个子女照顾两位老人

先注册或登录子女账号。本人角色单独显示在账号区域，不占两个老人位置；当前不支持其他家属共同管理。登录后可进入本人角色，或添加、选择两位老人并代填健康资料。

每位老人拥有独立 GameState：任务与每日奖励、灵气与装备、初始抽卡依据与回执、健康属性、境界与首通、技能解锁与战斗记录全部隔离。切换同时刷新游戏人物、HUD 和页面上下文。家人姓名与修仙称号分开保存，基本信息编辑不重置成长。

代填资料始终绑定选定老人。分析期间禁止切换，可先返回取消；迟到响应不写入其他角色。文字和图片路径草稿只在当前运行中按老人保留，不写入角色存档。战斗结束或退出后再切换，抽卡先保存结果再允许切换。

schema 8 使用独立 owner 和最多两个 members，每个角色完整保存既有游戏状态。不同注册账号使用不同本机存档文件。切换、创建、编辑和业务操作均原子保存；旧进度经确认后导入当前账号，本人不占老人位置，明确的老人关系优先保留。

## 账号与本人角色修正（当前规则）

启动必须先注册或登录子女账号，密码由独立账号服务验证。当前本机服务提供用户名密码注册、登录、会话与退出，游戏进度按账号保存在本机，尚未公网部署或提供跨设备存档同步。

本人拥有独立角色，不属于老人列表。界面上方显示“我的角色”，下方保留两个完整老人位置；本人和两位老人各自持有完整游戏状态。schema 8 单独保存 owner 与最多两个 members。旧角色导入时优先识别明确关系：原单角色与未填写关系的旧本人归回 owner，明确父亲、母亲等关系者留在 members。旧进度导入需明确归属当前账号，并保留原文件备份。
